# Harness Hub v0.1.0-alpha.4

> **Pre-release draft.** This release has not yet been built or published. Do not treat the planned installer, checksum, or pending verification as available or passed until the release plan records real output.

Harness Hub is a local-first desktop control center for discovering AI coding Harnesses, launching and managing sessions, and reviewing project activity and usage.

## What’s included

Compared with v0.1.0-alpha.3, this release candidate includes:

- **Project Registry:** register Git repositories by path; Harness Hub resolves the repository root and reuses the same project record for repeated registration.
- **Activity Timeline:** review usage and managed-session activity alongside the existing dashboard.
- **Multiple Harness capability boundaries:** Codex and Claude Code support the currently implemented lifecycle; Gemini CLI and OpenCode have detection and headless lifecycle support with machine-dependent GUI/auth readiness; CodeBuddy is detection-only. Usage support varies by Harness.
- **Plugin host v0.1:** out-of-process plugin discovery with two IPC commands, `plugin_list` and `plugin_refresh`. The Rust service invokes a plugin's `usage/import` method during usage import. Skill content is fetched and cached during refresh, then returned in the plugin list response. There is no plugin management UI in this release.
- **Plugin host hardening:** enforce the 64 KiB stderr capture ceiling, validate usage plugin directory and manifest identity before launch, and mark a plugin degraded after relevant plugin call failures. Final acceptance is pending; see the release plan.

- `SHA256SUMS`: `待生成` — attach the checksum file after the build.

The installer is unsigned. Windows may show an unknown publisher or SmartScreen prompt. You need WebView2 Runtime to run the desktop app; Windows 11 usually includes it. Harness Hub does not bundle Codex, Claude Code, Gemini CLI, OpenCode, CodeBuddy, their credentials, or their authentication setup. Install and authenticate each Harness separately.

The built-in usage runner tries `ccusage` on `PATH`, then a user-configured command, then `npx --yes ccusage@20.0.24`. The npx fallback requires Node.js/npm and may download the pinned ccusage package to the local machine when it is not cached; session data is passed to that local process and is not uploaded by Harness Hub. The usage-connect plugin is an example in the source repository only; the installer does not preinstall it. The example uses only Python's standard library and its fixture; the Rust host parses its response, so it does not require an external ccusage executable. Other plugins may require their declared adapter dependencies.

## Known limitations

- Gemini CLI authentication is currently rejected by the provider on the tested machine, and GUI TUI rendering remains environment-dependent. Headless lifecycle evidence does not establish a successful authenticated GUI conversation.
- OpenCode headless lifecycle is covered, while the current GUI TUI rendering observation is blocked by a cross-Harness environment issue. Authentication readiness depends on the local OpenCode configuration.
- CodeBuddy is detection-only; launch, terminal, and usage capabilities are not implemented.
- Plugin host v0.1 has only `plugin_list` and `plugin_refresh` IPC commands, and no UI. Usage import is invoked through the Rust service; skills are fetched/cached on refresh and returned by the list command. Its permission decision log is observe-only and does not sandbox plugins or restrict their operating-system access.
- The source repository's usage-connect example requires Python but not an external ccusage executable, and is not preinstalled in the installer. The built-in usage runner may use PATH/configured ccusage or the pinned npx fallback described above.
- This is an alpha release. Installation, upgrade, and machine-specific Harness readiness should be evaluated with these limits in mind.
