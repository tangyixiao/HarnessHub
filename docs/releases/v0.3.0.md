# Harness Hub v0.3.0

> **Worktree / 并行版本（ROADMAP C 轨道）。** Downloads: [Release page](https://github.com/tangyixiao/HarnessHub/releases/tag/v0.3.0)。

## What's included（相对 v0.2.0）

- **Worktree 创建与状态（C10）**：Projects 页每张项目卡片的 Worktrees 区——
  列表（主树徽标 / detached / HEAD 短 sha，porcelain v1 有界解析）、
  创建对话框（`git worktree add -b` 或复用未检出分支，confirm 二次确认）。
  路径安全红线：目标不允许位于 repo_root 内部（absolute + canonicalize 双层检查）。
- **安全合并与清理（C11）**：worktree 行状态徽标（干净 / 修改 N 项，惰性查询）、
  「合并到主分支」（`--ff-only`：主树脏拒绝、非快进拒绝——绝不做 rebase/force）、
  「删除」（**只删干净树**：脏树列出计数拒绝、主树/bare 拒绝）。
  「创建 → 观察 → 合并 → 清理」闭环完成。
- **Session 绑定**：`start_terminal_in_worktree` IPC（cwd 与 worktree_path 一同落库）；
  Terminal 启动器选择 worktree 留后续迭代。
- 其余：v0.2 全部能力（只读回放 / FTS5 搜索 / 工具与子代理线程 / 恢复外部会话）。

## Known limitations

- harness capability `worktree` 仍为 false：C10/C11 是 **Hub 自身**的 worktree
  能力；「某个 harness 能否在 worktree 中跑」需要真机 E2E 取证后才翻 true。
- 合并只支持 fast-forward（保守第一版）：历史分叉时明确报错，请手动处理。
- 删除前有未提交修改会被拒绝（计数列在错误里）；不做强制丢弃。
- 沿用 v0.2：回放/搜索/恢复仅 Claude Code（capability 门控）。

_纪律不变：以上为本机 / CI 真实输出；未执行项不以「应该可以」表述。_
